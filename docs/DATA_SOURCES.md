# Zoning and property data rollout

Reviewed November 7, 2026. Priorities are an implementation order based on development use cases, not an econometric valuation ranking.

1. Cambridge, Somerville, Boston: building type, housing capacity, subdistricts, overlays and redevelopment.
2. Watertown, Everett, Chelsea, Revere: corridor redevelopment, industrial conversion and transit context. State atlas data is available for mapped districts in Watertown, Chelsea and Revere. Chelsea also has a dated municipal base-zoning snapshot. Prioritize current local rule and overlay verification in these cities, including Everett. Everett’s historical municipal map is connected for research.
3. Chicopee provides a tested addition and nonconforming-lot reference case.

The coverage endpoint lists all 351 cities and towns from [MassGIS municipal boundaries](https://www.mass.gov/info-details/massgis-data-municipalities), layer 1 of the published `TownSurveyGenCoast_gdb` service. Inventory, published state district screening and local base zoning are separate coverage levels.

## Municipality checkoff

The coverage API reports a base-map status for all 351 municipalities. In this release there are 14 municipal map connections, 11 historical references and 326 places awaiting a base-map connection. A connected map does not complete the municipality review. Check off local ordinance and amendment verification, overlay review, and parcel-specific capacity separately.

The February 10, 2026 [EOHLC Chapter 40R district table](https://www.mass.gov/info-details/chapter-40r-smart-growth-zoning) provides 67 named district leads across 53 municipalities. The tracker records only names and the snapshot date. It does not use the table to match a parcel, estimate a project or confirm current district boundaries.

Regional snapshots are kept as historical references. The [NMCOG layer](https://www.arcgis.com/home/item.html?id=a79a7b6d02c64614b548474db85e4430) documents a January 2023 compilation. It adds Billerica, Chelmsford, Dracut, Dunstable, Lowell, Pepperell, Tewksbury, Tyngsborough and Westford. Every match requires both the submitted municipality and the selected parcel geometry. The published data edit timestamp does not establish a later ordinance adoption date. The National Zoning Atlas was evaluated but is not imported because its [terms](https://www.zoningatlas.org/terms) restrict reuse, including commercial use.

## Matching and failure behavior

Property searches use the [Census Geocoder county subdivision](https://www.census.gov/data/what-is-data-census-gov/guidance-for-data-users/frequently-asked-questions/how-do-i-search-by-address-using-the-census-geocoder.html) to route lookups to the Massachusetts municipality. The geocoded mailing address stays visible. For example, a Hyannis mailing address can route to Barnstable for parcel, zoning, sales, permit and deed lookups. If the geocoder returns conflicting municipalities, the search asks for a more specific address. Parcel and deed verification each still require their own source match.

Municipal zoning uses the matched parcel polygon in EPSG:3857, converted from the existing local ground-foot approximation. District polygons are clipped to the parcel, duplicate records are unioned, and split districts or incomplete coverage cause the district to be withheld. Boundary touches and tiny GIS slivers do not establish a district. Constraint screening uses the GIS server's parcel intersection query and requests attributes only; boundary touches are conservatively included as screening flags. Entire citywide constraint geometries are not downloaded. Remaining district processing runs outside the async request loop, with an input-size limit. Each failed constraint query is marked unavailable; it never becomes “no mapped intersection.” Updates to local standards require a fresh source review.

Sales candidates use same-municipality, same-use-group and comparable-area screening, a three-year window, and a one-mile parcel-centroid distance. Polygon geometry is supported. Missing area, future dates, duplicate parcels and mismatched residential types are excluded. This still uses assessor last-sale records; the LA3 transaction feed, deed-level verification, permits and full statewide rule sets remain future integrations. Neither a median candidate price nor a GIS capacity field is presented as an appraisal.

## Permit history

The report loads permits on demand under Property records. Boston uses the City of Boston Approved Building Permits dataset and matches the selected assessor parcel ID. Cambridge uses the City of Cambridge Permit Finder and matches the map and lot. Somerville uses the city's historical Permits dataset with an exact normalized street-address match, and links to the current city lookup. Responses show up to eight records from the bounded city query, favoring development and occupancy records. Permit type, issued date, and status are shown as city-reported values. Permit history does not establish legal occupancy or completion, and a missing result does not establish that no permit exists.
